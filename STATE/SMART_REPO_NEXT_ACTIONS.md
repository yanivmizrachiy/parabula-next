# SMART_REPO_NEXT_ACTIONS

## מטרת ההמשך

להמשיך לשפר את הריפו רק במה שבאמת צריך, בלי לשבור דפי A4, בלי לערבב נושאים, ובלי למחוק קבצים לפני audit אמיתי.

## מה כבר מיוצב

- `PROJECT_RULES.md` עודכן כך שישקף טוב יותר את מצב `main`.
- חוויית המוצר מוגדרת כ-Topic First.
- `preview/all-pages.*` מוגדר כמסך עזר חי, לא כמסך הבית הראשי.
- ערבוב נושאים נאסר במפורש.
- מחיקה / מיזוג / העברת דפים נאסרו בלי אישור מפורש.

## מה בודקים אחר כך (קריאה בלבד קודם)

### 1. כפילויות / legacy ב-preview
לבדוק אם הקבצים הבאים עדיין נחוצים, בלי למחוק עדיין:
- `preview/phone.*`
- `preview/print-center.js`
- קבצי עזר ישנים סביב install / phone / print

### 2. סנכרון כללים מול קוד
לבדוק שאין פער בין `PROJECT_RULES.md` לבין:
- `preview/topics.*`
- `preview/all-pages.*`
- `preview/print.*`
- `meta/topics.json`

### 3. הפרדה נושאית
לבדוק שהנושאים נשארים מופרדים היטב ב-metadata וב-UI.
דוגמה קריטית:
- `משוואות`
- `משוואות ריבועיות`

### 4. קבצים מרכזיים ארוכים מדי
לבדוק בהמשך אם צריך refactor זהיר ל:
- `preview/topics.js`
- `preview/all-pages.js`
- `preview/print.js`
- `mobile-app.js`

### 5. backup/state sprawl
לבדוק האם תיקיות backup שנוצרו בזמן תיקונים צריכות להישאר כעדות היסטורית או לעבור בעתיד לאזור ארכיון מסודר יותר.
אין למחוק אותן עכשיו.

## מדיניות בטוחה

- קודם audit, אחר כך החלטה.
- לא מוחקים עכשיו.
- לא ממזגים נושאים.
- לא משנים שיוך של דפים.
- לא מוסיפים דמו.
- כל שינוי מבני אמיתי חייב להיכנס גם ל-`PROJECT_RULES.md`.

## הצעד החכם הבא

Audit ממוקד של duplicate-adjacent preview files, של תיקיות backup שנוצרו מתיקונים, ושל פערים עדינים בין כללים, metadata, ו-UI.
