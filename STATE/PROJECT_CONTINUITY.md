# PROJECT_CONTINUITY — parabula-next

מסמך זה נועד לשמור רצף עבודה ברור בין שיחות ובין כלי AI, בלי לגעת בדפי העבודה עצמם ובלי לערבב נושאים.

## 1. עיקרון עליון

- `PROJECT_RULES.md` הוא מקור האמת הראשי של הריפו.
- המסמך הנוכחי הוא שכבת רצף ותיעוד עד לעדכון מלא של `PROJECT_RULES.md` עצמו.
- אין לשנות דפי עבודה קיימים (`עמוד-N.html`) במסגרת עבודות סדר, מובייל, שחזור או תצוגה, אלא אם המשתמש ביקש במפורש.
- אין לערבב בין נושאים קיימים ואין לשנות סיווגי נושאים בלי הוראה מפורשת.

## 2. מה כבר קיים ועובד בריפו

- דפי העבודה הקנוניים נשארים בשורש בשם `עמוד-N.html`.
- ה-CSS הקנוני נשאר תחת `styles/pages/`.
- בסיס A4 נשאר `styles/a4-base.css`.
- Preview קנוני נשאר תחת `preview/index.html`.
- מטא-דאטה של דפים מונעת מתוך `meta/topics.json`.
- GitHub Pages פעיל דרך `.github/workflows/deploy-pages.yml`.

## 3. מה נוסף בפועל ב-2026-04-14

### 3.1 שכבת מובייל / טלפון

נוספו:

- `preview/phone.html`
- `preview/phone.js`
- `preview/mobile.css`
- `preview/manifest.webmanifest`
- `preview/icon.svg`
- `preview/sw.js`

מטרת השכבה:

- צפייה נוחה בטלפון בכל דפי העבודה הקיימים
- טעינת רשימת הדפים האמיתיים מתוך `meta/topics.json`
- חיפוש, סינון לפי נושא, ניווט קודם/הבא
- פתיחת עמוד, פתיחת האתר החי, והעברה למסלול הדפסה/PDF דרך העמודים האמיתיים

### 3.2 שכבת בטיחות / התאוששות

נוספו:

- `scripts/recovery-audit.mjs`
- `.github/workflows/recovery-audit.yml`

מטרת השכבה:

- לזהות חוסרים מבניים בריפו
- לזהות עמודים בלי CSS תואם
- לזהות חוסר ב-`styles/a4-base.css`
- לזהות חוסר במחלקת `page-N`
- לזהות inline CSS בדפי העבודה הקנוניים
- להפיק דוח JSON תחת `meta/audit/recovery-audit.json`

## 4. מה עדיין לא הושלם

- `PROJECT_RULES.md` טרם סונכרן בפועל עם כל התוספות של 2026-04-14.
- שכבת restore אוטומטית מלאה עדיין לא קיימת; כרגע יש detection/audit בלבד.
- שכבת המובייל עדיין דורשת polish והקשחה, בעיקר סביב installability וזרימת PDF/Print.

## 5. סדר העבודה הבא

1. לסנכרן את `PROJECT_RULES.md` עם כל מה שכבר נוסף בפועל.
2. לייצב את שכבת הטלפון בלי לגעת בדפי העבודה עצמם.
3. לשפר מסלול PDF/Print מתוך שכבת המובייל.
4. להוסיף שכבת restore בטוחה לפני כל עבודת ניקוי מסוכנת.

## 6. כללי עבודה מחייבים להמשך

- כל שדרוג חדש חייב להיות מתועד.
- כל שדרוג חייב להיות שכבת תשתית סביב הדפים, לא שינוי בדפים עצמם.
- כל שיחה עתידית צריכה להתחיל מבדיקה של `PROJECT_RULES.md` ושל `STATE/PROJECT_CONTINUITY.md` כדי להבין איפה ממשיכים.
