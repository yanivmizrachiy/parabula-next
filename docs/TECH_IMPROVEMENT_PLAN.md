# TECH_IMPROVEMENT_PLAN — תוכנית חיזוק טכנולוגי

_נכתב: 2026-07-10 · ניתוח מומחה של הטכנולוגיות ביצירת דפי העבודה, מה כדאי לשפר, ואילו כלים כדאי להתקין._

העיקרון המנחה (מ-PROJECT_RULES): לא מחליפים כלי עובד רק כי קיים חדש יותר. כל המלצה כאן נבחנה מול: איכות הדפסה, מהירות יצירת דפים, יכולת התרחבות לאלפי דפים, ותחזוקה.

---

## 1. מה עובד מצוין היום — לא לגעת

| טכנולוגיה | למה היא נכונה |
|---|---|
| HTML סטטי + CSS לדף | פשוט, מהיר, שורד שנים, מושלם להדפסה |
| MathJax 3 | רינדור נוסחאות ברמת ספר לימוד |
| SVG inline | וקטורי, חד בהדפסה, ניתן לעריכה בקוד |
| Vite + GitHub Actions → Pages | פריסה אוטומטית אמינה (אחרי תיקון ה-lockfile) |
| בדיקות חוזה (node:test) | 99 בדיקות בלי תלות חיצונית |
| Playwright | אודיט A4 חזותי + ייצוא PDF — כבר מותקן |

## 2. שיפורים מומלצים — לפי סדר עדיפות

### עדיפות 1 — למזג את PR #28 (eqmerge) — אפס התקנות
ההמרה של 52 דפי המשוואות ל-HTML+MathJax חי היא שדרוג הטכנולוגיה הגדול ביותר האפשרי:
מבטלת את תלות התוכן בתמונות, פותרת חריגות A4, מיישרת CI, ומביאה מדריך יצירת דפים מלא.

### עדיפות 2 — עצמאות מ-CDN להדפסה (self-hosting)
**הבעיה:** Rubik ו-MathJax נטענים מ-CDN — הדפסה בלי אינטרנט לא עובדת מיטבית, וה-CDN הוא נקודת כשל יחידה.
**הפתרון:** להוריד את MathJax (tex-mml-chtml.js) ואת קבצי Rubik (woff2) לתיקייה `vendor/` ולהחליף את הקישורים ב-98 הדפים בסקריפט אוטומטי.
**רווח:** הדפסה עובדת תמיד, טעינה מהירה יותר, אפס תלות חיצונית. **התקנה:** כלום — רק הורדת קבצים.
(שינוי ב-`עמוד-N.html` — דורש אישור יניב; הסקריפט יוכן מראש ויוחל בפעולה אחת.)

### עדיפות 3 — מחולל גרפי פונקציות (הכלי החסר המתועד)
CLAUDE.md מגדיר את זה כחסר: פרבולה, קו ישר, עלייה/ירידה. במקום לצייר SVG ידנית לכל דף —
סקריפט `scripts/generate-function-graph.mjs` שמקבל `{type, params, domain}` ופולט SVG תקני
(440px, grid 22px, non-scaling-stroke, labels בעברית). זה מכפיל את מהירות יצירת דפי הפונקציות/גרפים.
**התקנה:** כלום — Node טהור.

### עדיפות 4 — ולידציית HTML אמיתית: `html-validate`
**מה זה נותן:** תופס תגיות לא סגורות, id כפולים, שגיאות מבנה שהבדיקות הנוכחיות (מבוססות-מחרוזת) מפספסות.
**התקנה:** `npm i -D html-validate` (קל, בלי דפדפן), חיבור כ-gate ב-ci:all על `עמוד-*.html`.

### עדיפות 5 — סכימת JSON אמיתית: `ajv`
`validate-meta-schema.mjs` כתוב ידנית. עם `ajv` + קובץ סכימה ב-`schemas/` מקבלים ולידציה מלאה
של meta/topics.json (טיפוסים, שדות חובה, uniqueness) — קריטי כשמגיעים לאלפי דפים.
**התקנה:** `npm i -D ajv`.

### עדיפות 6 — בסיס תמונות ייחוס (visual regression)
Playwright כבר מותקן; חסר baseline. לשמור צילומי מסך מאושרים של כל דף ולהשוות בכל שינוי —
כך אף שינוי CSS לא ישבור דף קיים בלי שנדע. **התקנה:** כלום — הרחבת הסקריפט הקיים.

## 3. מה לא מומלץ (נבחן ונדחה)

- **מעבר ל-Next.js/Astro/React** — אפס רווח לדפי הדפסה סטטיים; סיכון גבוה. (הוחלט בעבר, נשאר בתוקף.)
- **Puppeteer** — מיותר; Playwright כבר עושה הכול.
- **Tailwind/frameworks ל-CSS** — ה-CSS-לדף הנוכחי scoped ופשוט; framework יוסיף משקל בלי רווח.
- **Prettier על דפי עבודה** — פורמוט אוטומטי של 98 דפים = diff ענק וסיכון; לא שווה את זה.
- **TypeScript לסקריפטים** — נחמד, לא דחוף; לשקול רק כשהסקריפטים יגדלו משמעותית.
