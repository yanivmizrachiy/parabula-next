# מערכת משוואות בשני נעלמים — קישור, אוטומציה ובקרת איכות

הפרק מנוהל כחוברת רציפה שמתחילה בעמוד `609` ומסתיימת בעמוד `616`.

## פתיחת החוברת

הכתובת `systems-workbook.html` היא שער חכם וקבוע. היא אינה מתחזקת קורא שלישי ואינה משכפלת את מנגנון הניווט:

- במחשב היא פותחת את `catalog.html?file=עמוד-609.html`, הקורא הקנוני של האתר, ישירות בדף המבוקש.
- בטלפון ובמכשיר מגע קומפקטי היא פותחת את `mobile-app.html?file=עמוד-609.html`.
- אפשר להעביר לשער פרמטר `file=עמוד-N.html` כדי לפתוח כל דף אחר.
- שני הקוראים מעדכנים את פרמטר `file` בזמן דפדוף, ולכן אפשר להעתיק ולשתף את כתובת הדף הפעיל בכל מכשיר.
- לחיצות ניווט וקיצורי מקלדת יוצרים היסטוריית דפים, וחזרה/קדימה בדפדפן מחזירות את הדף המתאים.
- בקורא הנייד, חזרה לדף בנושא אחר נטענת מחדש מהכתובת הקנונית כדי לשחזר גם את הנושא וגם את הדף בצורה אמינה.
- הפתיחה הישירה אינה תלויה בערך השמור של הדף האחרון; הערך השמור נשאר רק כברירת מחדל כשאין פרמטר בכתובת.
- הקישור הישן נשמר, ולכן סימניות וקישורים שכבר נשלחו ממשיכים לעבוד.
- דפי העבודה עצמם אינם משתנים ואינם מעוצבים מחדש על ידי השער או הקוראים.

הקוראים הקנוניים קוראים את הנתונים מ־`meta/topics.json`. מבנה החוברת וספירת המשימות נבדקים מול `meta/two-variable-systems-manifest.json`.

## פקודות עבודה

- `npm run systems:audit` — מציג את מצב החוברת: מספר דפים, מספר משימות, סדר הדפים וחלוקה לפי סוגי משימות.
- `npm run systems:manifest:check` — מוודא שה־manifest תואם למצב בפועל.
- `npm run systems:manifest:write` — מעדכן את ה־manifest לאחר שינוי מכוון בתוכן או בסדר הדפים.
- `npm run systems:ci` — מפעיל את כל בדיקות החוזה הייעודיות לפרק, לשער ולקוראים הקנוניים.

## מה נבדק אוטומטית

1. שרשרת הניווט בין כל דפי החוברת, כולל העמוד שלפניה והעמוד שאחריה.
2. מיקום כל דף בתוך החוברת והמספור המודפס.
3. קיום כותרת הנושא וקישור פעיל לעמוד הפתיחה.
4. קיום קובץ CSS לכל דף וייבוא שכבת העיצוב המשותפת.
5. מספר המשימות בכל דף והחלוקה למערכות, בעיות מילוליות, מיון פתרונות, אתגרים וחשיבה מתמטית.
6. התאמה בין סדר הדפים בפועל לבין `meta/systems-drive-sync.json`.
7. התאמה מלאה ל־`meta/two-variable-systems-manifest.json`.
8. שער ההפניה מעביר את `file` ישירות לקורא המחשב ולקורא הנייד.
9. קורא המחשב מסנכרן כתובת והיסטוריה באמצעות `catalog-deep-link.js`.
10. הקורא הנייד מסנכרן כתובת והיסטוריה באמצעות `mobile-deep-link.js`, כולל שחזור בין נושאים.
11. בדיקת האתר החי מאמתת את השער, שני הקוראים, שני בקרי הקישור וכל דפי החוברת לאחר כל פריסה.

כל שינוי שמשפיע על הפרק, על שער החוברת או על אחד מבקרי הקישורים מפעיל workflow ייעודי ב־GitHub Actions.
